Hosted tools are tools the model provider executes *inside* the generate request — OpenAI's web search / code interpreter / file search, Anthropic's web search / code execution, or any AI SDK provider tool via `hostedTool()`. The SDK never runs them: it sends them alongside function tools and reports the calls the provider made (N1a/N1b).

## Entry points

- `src/tools/hosted.ts` — `webSearch()`, `codeInterpreter()`, `fileSearch()`, `hostedTool()`, `HostedTool`, `HostedToolType`, `isHostedTool()`, `assertHostedToolNames()`, `hostedToolUnsupported()`.
- `src/createAgent.ts` — `splitHostedTools()` (`createAgent.ts:1047`): separates `tools` into local descriptors and hosted tools.
- `src/execution/hostedToolCalls.ts` — `assertHostedToolsSupported()`, `withHostedCalls()`, `settleHostedFinish()`, `countHostedCalls()`, `cappedHostedResult()`, `HOSTED_RESULT_LIMIT` (20,000 chars).
- `src/providers/aiSdkProvider.ts` — `supportsHostedTool()`, `hostedToolsFor()`, `splitHostedTools()`, `mapsHostedTools` flag.
- `src/providers/OpenAIProvider.ts` — `OPENAI_HOSTED_TOOLS` mapping table; `AnthropicProvider.ts` — `ANTHROPIC_HOSTED_TOOLS` + `newestFactory()`; `OpenRouterProvider.ts` — maps `web_search` to OpenRouter's plugin interface.
- `src/providers/hostedToolMapping.ts` — `mappedHostedOptions()`, `HostedOptionMapping` (helper option → provider argument, `undefined` = not supported).
- `src/execution/permissions.ts` — `hostedToolsInMode()`, `READ_ONLY_HOSTED_TYPES` (plan-mode filtering).

## How it works

**Helpers produce inert descriptors.** `webSearch({ maxUses, allowedDomains, ... })` returns a frozen `{ kind: 'hosted-tool', name: 'web_search', type, options }` — no `execute`, no schema. `hostedTool(name, aiSdkTool)` wraps an arbitrary AI SDK provider tool (`type: 'custom'`), passed through untouched. Because they're not descriptors, `ToolRegistry.registerMany()` refuses them outright ("hosted tools run on the provider and cannot be registered"); they only enter via `createAgent({ tools })`, where `splitHostedTools()` pulls them out — in record form the key must equal `tool.name`, since the provider maps by it. `assertHostedToolNames()` throws on a hosted tool sharing a name with another hosted tool or a local tool.

**Per-call mapping.** Before a run, `assertHostedToolsSupported()` asks the provider's `supportsHostedTool(type)` — the base implementation accepts only `'custom'` on `ai` 6/7; providers that map built-ins override it. On each `generate()`, the provider's `hostedToolsFor()` turns the helpers into real AI SDK tool objects: OpenAI maps to `openai.tools.webSearch()`/`codeInterpreter()`/`fileSearch()`; Anthropic maps `web_search` to the newest `tools.webSearch_*()` it finds and `code_interpreter` to `codeExecution_*()` (Anthropic's name — events keep ours); `file_search` has no Anthropic equivalent and throws `LOUSHO_HOSTED_TOOL_UNSUPPORTED`. The mapped objects merge into the request's tool set in `aiSdkCompat.ts:modernToolSet()`.

**Option mapping is a lookup table.** `OPENAI_HOSTED_TOOLS`/`ANTHROPIC_HOSTED_TOOLS` give each `HostedToolType` a factory plus a `HostedOptionMapping`: e.g. OpenAI takes `searchContextSize`, `userLocation` (wrapped as `{ type: 'approximate' }`), `allowedDomains` → `filters.allowedDomains`, and drops `maxUses`/`blockedDomains` (Anthropic-only); `fileSearch`'s `maxResults` becomes `maxNumResults`. `mappedHostedOptions()` drops options the provider can't take with one `console.warn` per `provider:tool:options` key per process — so an option unsupported on one provider degrades instead of failing.

**Results flow back through the provider.** The provider returns `hostedToolCalls` on its `GenerateResult`. The executor (`AgentExecutor.ts:1036`+): counts them in `usage.hostedToolCalls`, stamps them onto the step's assistant message as `metadata.hostedToolCalls` (each call JSON-safed, its result capped at `HOSTED_RESULT_LIMIT` characters of JSON, sources kept as `{url, title}`), and emits events with `executedBy: 'provider'`. `settleHostedFinish()` handles the corner case: a step whose only calls are hosted reports `finishReason: 'tool_calls'` but has nothing for the loop to run — it's rewritten to `'stop'` so the run doesn't ask the model again with nothing new.

**Permissions see them only at the coarsest level.** A hosted call is invisible to validation, hooks, guardrails, `needsApproval`, and `onToolCall` — it happened inside the provider. The one control is `hostedToolsInMode()`: in `plan` mode only `READ_ONLY_HOSTED_TYPES` (`web_search`, `file_search`) are sent at all; `code_interpreter` runs code and `custom` is unknown, so they're withheld from the request entirely.

## Design decisions

- **No local execution path, deliberately.** Provider tools need provider infrastructure (search index, sandboxed container, vector store); a local shim would be a different feature. The type is `kind: 'hosted-tool'` marker, not a descriptor, which is why the registry rejects it rather than silently dropping `execute`.
- **Mapping tables over abstraction.** Each provider's mapping is a plain `Record<HostedToolType, {factory, options}>` — easier to audit than a generic option translator, and unsupported options fall out naturally as `undefined` entries.
- **Warn-once for dropped options.** Failing would break cross-provider agents; warning every call would spam. One warn per distinct drop-set is the compromise.
- **Provider runs ⇒ executor only observes.** The transcript keeps hosted calls as assistant-message metadata (not `tool` messages — there was no client-side call to answer), which keeps replay and session stores consistent without inventing fake tool calls.
- **`fileSearch` validates eagerly.** It needs `vectorStoreIds` at creation (a missing/empty list throws `LOUSHO_CONFIG_INVALID`) because the provider-side failure would surface only inside a model call — far harder to diagnose.
- **Pass-through is version-gated.** `hostedTool()` objects reach the provider as-is only on `ai` 6/7 (`aiSdkProvider.splitHostedTools`); on older majors the same `LOUSHO_HOSTED_TOOL_UNSUPPORTED` error explains what would work.

## Example

```ts
import { createAgent, webSearch, fileSearch } from '@lousho/build-ai-agent';

const agent = createAgent({
  model: 'openai/gpt-4o-mini',
  tools: [
    webSearch({ searchContextSize: 'low', allowedDomains: ['docs.example.com'] }),
    fileSearch({ vectorStoreIds: ['vs_abc123'] }), // throws if vectorStoreIds is empty
    localTool, // local and hosted tools mix freely
  ],
});
// The provider runs searches inside the request; results land on
// message.metadata.hostedToolCalls and usage.hostedToolCalls.
```
