# Entry Point

Two surfaces: `createAgent({ output })` — a model turn constrained to a zod schema returning `result.object` (`{route, confidence, reason}`), branched on by flow `oneOf` ([structured output](/providers/structured-output)) — and `decide()` (`src/decisions/decide.ts`, root-exported via `src/decisions/index.ts`), a dedicated client for the OpenAI Decisions API (`POST {baseURL}/decisions`). `validateQuestions` enforces unique names, non-empty choices, ≥2 levels.

# Background

## Rationale

Some workflow steps shouldn't generate prose — they should *decide*: classify, route, score, verify. The TypeSafe Jev pattern makes this a typed probabilistic decision: unstructured state in, `{action, confidence}` out, workflow branches on it. A prose reply can't gate a branch; a validated schema field can.

## Problem Statement

How do workflows get fast, typed, calibrated decisions — including a confidence floor that escalates low-confidence calls to a human — without losing the answer's type or conflating a dedicated decisions endpoint with a model turn?

## Business Value

Routing/scoring becomes a typed, testable contract instead of prompt parsing. The `decide()` path is ~10× faster than a full model turn and returns real probability distributions — cheaper, faster, and honest about confidence.

# Goal

### Primary Goal

Two interchangeable implementations of the same pattern: `output`-schema (any provider, inside a pipeline) and `decide()` (OpenAI-only, standalone) — both yielding typed `{action/value, confidence}` a `oneOf`/caller branches on, with a floor that converts "can't decide" into a first-class outcome.

### Secondary Goals

- `decide()` supports all four question types (`predicate`/`choice`/`score`/`refusal`) with calibrated `probabilities`/`confidence`.
- Batch independent questions into one request (the API's shape), validated client-side.

# Scope

## This project is for

- Classify/route/score steps where a typed answer — not prose — is the deliverable; confidence-gated escalation.

## This project is not for

- Decisions needing evidence-gathering — neither form reasons with tools; those want a sub-agent or flow.
- Provider-agnostic `decide()` — it's OpenAI-only (beta); the `output` form is the portable path.

# Solution

The `output` route: `createAgent({ output: z.object({action, confidence, reason}) })` → validated `result.object` → flow `oneOf` on `d.action` + `d.confidence >= floor`; below-floor escalates to the safe path. The `decide()` route: one `POST /decisions` with `{input, questions[]}` → `answers[]` mirroring question `name`s — predicate → `probability`, choice → `choice` + `probabilities` + `confidence`, score → weighted index, refusal → `{type:'refusal'}`. Response is zod-validated; errors map to standard `LOUSHO_*` codes.

# Other Solutions

- **Routing `decide()` through `LLMProvider`** — rejected: the endpoint isn't chat-completions (no messages→text, no tools, no streaming, response is a distribution). Faking `Message[]` and flattening `probabilities` into text loses what the endpoint is for. OpenRouter can't reach it either — the provider abstraction couldn't reach it even if wanted.
- **Model reply drives action without a floor** — rejected: a classifier that always answers still guesses; `confidence < 0.7 → careful path` converts "decide" into "decide or escalate". Unparseable replies degrade to zero confidence rather than a default route — "cannot decide" is itself an outcome.
- **One question per call** — rejected: the API's shape is shared `input` + batched `questions`; `answers` echo `name`s.

## Challenges

- **Beta endpoint** — `gpt-6-luna` only; the surface may change. Mitigation: zod validation turns a shape change into `LOUSHO_PROVIDER_REQUEST_FAILED`, not silent garbage.
- **Refusal is a first-class answer** — callers must handle `{type:'refusal'}`; no default.
- **`output` confidence is self-reported prose-calibration** — a real distribution only exists on `decide()`.

# Implementation considerations

- **Provider surface stays clean**: `decide()` bypasses `LLMProvider` deliberately — providers stay provider-agnostic while the beta API is isolated in `src/decisions/`.
- **Config**: `OPENAI_API_KEY` default, overridable `baseURL`/`apiKey`/`model`/`timeoutMs`/`signal`/injectable `fetch` for tests.
- **The gate stays downstream**: a `patch` decision flows through the same approval/permission machinery as any other tool call — typed decisions select the path, they don't loosen it.

## Example

```ts
const { answers } = await decide({
  input: 'I was charged twice for my order.',
  questions: [{ type: 'choice', name: 'route', instructions: 'Which team?',
    choices: [{ value: 'billing' }, { value: 'other' }] }],
});
const route = answers[0];
if (route.type === 'choice' && route.confidence >= 0.7) dispatch(route.choice);
else escalateToHuman();
```
