## The decision

Where the SDK must later recognize "an object I made", it uses a runtime mark rather than TypeScript's structural typing or compile-only branded types. Three forms exist, chosen by who must share the mark:

- **`Symbol.for` brand + `Symbol.hasInstance`** (LOU-D42, `src/utils/brand.ts`): a class whose identity must survive duplicated SDK copies. `SDKError` and `HookRegistry` carry a `get [Symbol.for('lousho.*')]` on the prototype and a static `Symbol.hasInstance` that calls `instanceOfBranded()`: for the *base* class, any object showing the brand passes `instanceof`; for subclasses the default check runs, so only the base identity is equated across copies.
- **Private `unique symbol` keys** (`Symbol('lousho.*')`, *not* `Symbol.for`): internal channels smuggled through public option objects — `RUN_EVENTS` on `ExecuteOptions` (`src/execution/agentRun.ts`), `PROVIDER_EVENTS` on generate options (`src/providers/providerEvents.ts`), `TOOL_DEFERRAL` (`src/execution/toolDeferral.ts`), `CODE_MODE` (`src/execution/codeMode.ts`). The field is unforgeable and unguessable without the symbol, invisible in the public type surface, and costs nothing at rest.
- **`Symbol.for` slots on `globalThis`**: `lousho.providerInterceptor` (`src/providers/interception.ts`) — deliberately the *shared* variant, because the interceptor is process-wide and the CJS and ESM bundles must see the same one.
- **Non-enumerable result brands**: `todo_write` marks its result with `Symbol.for('lousho.todoList')` via `Object.defineProperty(..., enumerable: false)` so a run recognizes it to emit `todo.updated` — surviving renamed or wrapped tools — while `JSON.stringify` never sees the mark (`src/tools/built-in/todo.ts`).
- **WeakSet marks**: `remoteAgent()` products live in a module-private `WeakSet` (`src/subagents/remoteAgent.ts`), handoff registrations in a `WeakMap` (`src/handoffAgents.ts`) — membership can't be forged by a duck-typed lookalike.

## Alternatives rejected

- **Plain `instanceof`.** Breaks under the dual-package hazard: a process that loads both the CJS and ESM build (or two nested copies) gets two class identities. The brand makes `error instanceof SDKError` hold either way.
- **`error.name` / `.constructor.name` checks.** Minification renames them and any object can fake them. The codebase does use a `name` check for `CassetteMismatchError` — but only as a fallback alongside the branded `instanceof SDKError` (`isCassetteError`, `src/execution/errors.ts`).
- **Compile-time nominal types** (`type SessionId = string & { __brand: ... }`). Not used for ids: a `sessionId` is just a `string`, validated at trust boundaries by `assertSessionId` (`src/session/sessionId.ts`) because ids become file names. Nominal id types would force every consumer to cast or wrap, buy nothing at runtime, and can't help the dual-copy problem at all — the brands solve the problem that actually exists (runtime recognition across copies), so the type system is left alone. *(Inference: no branded-id types exist anywhere in `src/`; the validation-at-boundary pattern is what the code does instead.)*
- **`Symbol.for` for the private channels.** A registered symbol is reachable by anyone who knows its name — precisely what `RUN_EVENTS` & co. must not be, since they carry internals consumers shouldn't set.

## Where it shows up

Contributor ripples: a new error class automatically participates via `SDKError`'s inherited brand getter — no per-subclass work. But adding a class whose `instanceof` must survive copies means wiring `Symbol.for` + `instanceOfBranded` by hand (copy `HookRegistry`). And a `unique symbol` option is invisible to object spread and `JSON.stringify` — features that need to serialize options can't see those fields.

## Trade-offs accepted

- The brand is a getter on the prototype, so subclass instances of a *foreign* copy pass `instanceof SDKError` but not `instanceof ConfigurationError` — cross-copy checks are only reliable on the branded base. Code branches on `error.code` for the fine-grained case anyway.
- `unique symbol` channels are per-copy: an options object built by one copy can't smuggle its hidden field into another copy's call. Accepted because these channels are internal-only.
- `Symbol.for` brands are spoofable by a determined consumer — they guard against *accidental* identity loss, not adversarial objects; the `WeakSet` marks cover the cases where forgery would matter.

## Example

```ts
// src/utils/sdkError.ts — the pattern every cross-copy class copies
const SDK_ERROR_BRAND = Symbol.for('lousho.SDKError');

export class SDKError extends Error {
  static [Symbol.hasInstance](value: unknown): boolean {
    return instanceOfBranded(this, SDKError, SDK_ERROR_BRAND, value);
  }
  get [SDK_ERROR_BRAND](): true {
    return true;
  }
}
```

```ts
// src/execution/agentRun.ts — a private channel on a public options type
export const RUN_EVENTS: unique symbol = Symbol('lousho.agentRunEvents');
export type StreamingExecuteOptions = ExecuteOptions & { [RUN_EVENTS]?: RunEventSink };
```
