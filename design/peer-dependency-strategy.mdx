# Entry Point

`loadOptionalPeer()` / `lazyValue()` / `FEATURE_PEERS` / `MissingPeerDependencyError` (`src/providers/optionalPeer.ts`) — the loading seam every optional peer goes through. `peerInstallCommand` (`src/providers/providerSpec.ts`) computes the install line; `aiMajorOf` (`src/providers/aiSdkCompat.ts`) detects the `ai` major; `src/providers/importGraph.test.ts` enforces the laziness contract on every built entry point.

# Background

## Rationale

`@lousho/build-ai-agent` supports OpenAI, Anthropic, OpenRouter, Ollama, MCP, Docker sandboxes, QuickJS, React/Vue — but any one consumer uses a fraction. Paying the install/bundle/audit cost for unused providers is a tax on every `npm install`.

## Problem Statement

How does the SDK ship support for many heavy integrations without forcing every consumer to install them — and without a missing package crashing `import '@lousho/build-ai-agent'` at load time?

## Business Value

Install footprint stays minimal; adding a provider doesn't grow everyone's tree. The peer matrix (`ai` 4–7 × zod 3–4) lets the SDK ride ecosystem upgrades instead of pinning consumers.

# Goal

### Primary Goal

Zero optional peers load at import time; a missing one surfaces at first *use* as `LOUSHO_PEER_MISSING` with the exact `npm install` command — computed against the installed `ai` major.

### Secondary Goals

- One source tree supports `ai` 4/6/7 and zod 3/4 (`AI_RANGES`, `zodCompat`).
- The worker bundle keeps `node:` out except a fixed importer allowlist.

# Scope

## This project is for

- The 14 optional peers (provider + feature packages) and the two required peers (`ai`, zod); compat layers for both; the import-time laziness contract; worker `node:` shims.

## This project is not for

- Auto-installing missing packages — the error *reports* the command, never runs it.
- Automatic support for a *new* `ai` major — export-sniffing in `aiMajorOf` is extended deliberately, not dynamically.
- Missing *transitive* modules — a broken install is reported as-is, not as `LOUSHO_PEER_MISSING` (`isMissingPackage` checks the specifier).

# Solution

`loadOptionalPeer` wraps a literal dynamic `import()` — module scope never holds one — and translates `MODULE_NOT_FOUND`/`ERR_MODULE_NOT_FOUND` into `MissingPeerDependencyError` whose `installCommand` is ai-major-aware (`@ai-sdk/openai@^0.0.42` on ai 4, `^4.0.0` on ai 7). `lazyValue` caches success, never failure, so installing-then-retrying works. `aiSdkCompat` maps the v4↔v6/v7 request/response/stream shapes (`aiMajorOf` sniffs *exports*: `stepCountIs` ⇒ v5+, `registerTelemetry` ⇒ v7). `zodCompat` compiles against `zod/v4/core` which exists in both zod majors. For Workers, `workerNodeShimPlugin` rewrites `node:*` only for a fixed importer allowlist and a post-build leak check fails the bundle if anything else reaches `node:`.

# Other Solutions

- **Real dependencies** — rejected: every consumer pays for providers they never use.
- **Static imports** — rejected: a reachable `import '@ai-sdk/openai'` crashes the whole package load; the failure is Node's opaque resolution error, not a named one.
- **`require('ai/package.json')` version detection** — rejected: breaks under bundlers and aliased packages (`ai-v6`/`ai-v7` in devDeps); export-sniffing survives both.

## Challenges

- Dynamic `import()` needs a literal specifier (bundlers must keep it external) — no variable package names.
- Missing peers surface at first *use*, not `npm install` — `dockerode` is discovered when `SubprocessSandbox` first runs; `lousho doctor` and the error's install line mitigate.
- Compat types are `never`-shaped at the boundary (`AiSdkModule` uses `options: never`).

# Implementation considerations

- **The leak check is the guardrail**: `importGraph.test.ts` loads every entry point under a resolver-recording hook — a static peer import added anywhere reachable fails CI. The worker's `node:` allowlist is the same trap on a different axis.
- **Adding a peer**: literal `import()`, `FEATURE_PEERS` entry, peer install-command mapping, and a check the import-graph test still passes.
- **The dual-copy hazard** this strategy creates (two package formats × optional peers × dual majors) is exactly what [branded types](/design/branded-types) solves.

## Example

```ts
// src/providers/OpenAIProvider.ts — the idiom every optional peer uses
private readonly loadProvider = lazyValue(async () => {
  const { createOpenAI } = await loadOptionalPeer(
    '@ai-sdk/openai',
    () => import('@ai-sdk/openai'),
    aiMajorOf(this.ai),
  );
  return createOpenAI(this.config);
});
```
