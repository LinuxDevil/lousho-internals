## Errors

- User-facing failures are `SDKError` with a stable `code` from `src/utils/errorCodes.ts` — the code gets a one-line fix hint and a docs link appended automatically.
- `appendHelp: false` when the message goes back to the model (tool/provider errors) — the model doesn't need the hint line.
- Errors carry `detail` (clean message) vs `message` (message + `[code] hint (docs)`).

## Types and validation

- Zod for anything crossing a boundary: tool inputs (`input:` schema, not `parameters`), specs, API responses.
- Branded types + `Symbol.for` instanceof for values that must survive duplicated SDK copies (see [branded types](/design/branded-types)).
- Optional heavy deps load through `loadOptionalPeer` — never a static import; missing peers throw `MissingPeerDependencyError` with the exact `npm install` line.

## Style

- Compact, no dead exports — `fallow` gates unused exports and per-function complexity (cyclomatic/cognitive; CRAP uses real coverage).
- No `any` (lint errors); test helpers use typed fakes.
- Comments explain *why*; the code says what. Don't delete existing comments.

## Tests

- Offline by default: `mockModel([...])` scripts turns including `{ error }` entries.
- Fixture dirs use `mkdtemp` — never write into the repo from tests.
- `*.live.test.ts` guards on env keys; `*.replay.test.ts` replays cassettes; `*.test-d.ts` asserts types.

## Design documents

New `design/*.mdx` pages follow the technical-design template — this is the baseline every ADR-style page extends:

```mdx
# Entry Point          — where the feature lives (files, symbols, API surface)
# Background           — ## Rationale, ## Problem Statement, ## Business Value
# Goal                 — ### Primary Goal (SMART), ### Secondary Goals
# Scope                — ## This project is for / ## This project is not for
# Solution             — the design in detail, system design where applicable
# Other Solutions      — rejected alternatives + why; ## Challenges
# Implementation considerations — monitoring, environments, security, perf
## Example / ## Where next — working snippet + cross-links (extension)
```

Keep the six template sections even when a section is short — the uniformity is what makes the ADRs scannable.

## Docs and exports

- `docs/*.md` is the source of truth; `E:\agent-sdk-docs` renders it via `scripts/sync-sdk-docs.mjs` (add your page to its `PAGES` map and `docs.json` nav).
- Example READMEs sync too — an `examples/<name>/README.md` becomes a docs page when mapped.
- Never commit secrets, API keys, or cassette auth headers; the cassette format is scrubbed, but check `git diff` anyway.
