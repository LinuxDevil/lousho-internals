---

`createAgent({ output })` / `ExecuteOptions.output` give a run a schema its final reply must satisfy. The machinery is small: `src/execution/structuredOutput.ts` renders the schema into a prompt block and a `responseFormat` hint, and `AgentExecutor.checkOutput()` runs the parse → validate → one-repair-step → `'output-invalid'` sequence.

## Entry points

- `ExecuteOptions.output?: StandardSchemaV1` — `src/execution/AgentExecutor.ts`; `createAgent({ output })` types `result.object` as `InferSchemaOutput<T>` (zod 3, zod 4 or any Standard Schema with JSON Schema output).
- `outputInstruction(schema)` — the `## Output format` system-prompt block.
- `outputResponseFormat(schema)` — `{ type: 'json', schema }` for `GenerateOptions.responseFormat`.
- `validateOutput(schema, text)` — unfence → `JSON.parse` → `parseWithIssues`; returns `{ object }` or `{ outputError }`.
- `outputRepairMessage(error)` — the `[output-invalid]` user message of the repair step.
- `OutputError` — `{ message, issues: [{ path, message }] }`, surfaced as `result.outputError`.

## How it works

**Request side** (`prepareGenerateRequest`, `generateStep.ts`): `outputInstruction()` is appended last to the system prompt (after the plan-mode block); every model call of the run carries `responseFormat: outputResponseFormat(output)`.

- The schema is converted once and cached in a `WeakMap` (`jsonSchemaOf`): zod 4 / Standard Schema via `schemaToJsonSchema()` (draft-7), zod 3 via the `ai` SDK's `zodSchema()` converter.
- `closeObjectSchemas()` then sets `additionalProperties: false` on **every object node that doesn't set it** (LOU-R7): OpenAI-compatible strict structured-output endpoints reject open object schemas, and zod 4's `toJSONSchema` doesn't emit it. An explicit `additionalProperties` (`z.strictObject`, `z.looseObject`, `record`, `catchall`) is left alone — it says what the author meant.

**Provider side.** `responseFormat` is a hint: `AiSdkProvider` maps it to `experimental_output` on `ai` v4 (`toOutput`, schema only when `model.supportsStructuredOutputs`) and to an `output` object on v6/v7 (`toModernOutput` — JSON mode, prompt and reply text untouched); `PiProvider` sends `response_format: json_schema`/`json_object` through `samplingParams`. A custom provider may ignore it — validation is the contract, not the hint.

**Reply side** (`checkOutput`, `AgentExecutor.runSteps`): when a step finishes with `stop`, `validateOutput()` unfences the reply (one ```` ```json ```` fence tolerated), parses it, and validates with the schema's own `safeParse`/`~standard.validate` — so zod defaults and transforms apply to `object`.

```text
valid        → result.object = parsed data, run finishes 'stop'
invalid      → canRepair? push outputRepairMessage, take ONE more step
               : finishReason = 'output-invalid', result.outputError set
```

## Design decisions

- **Exactly one repair step** (`repaired` flag in `runSteps`). More repair turns don't converge — a model that didn't match the schema after seeing its issues listed usually won't on attempt three — and each retry burns budget and latency. The step counts against `maxSteps` (`canRepair = !repaired && state.steps < maxSteps`), so a spent budget goes straight to `'output-invalid'`.
- **Resolve, don't reject.** An invalid output is a result (`finishReason: 'output-invalid'`, `outputError`), not a throw — retries/fallback classify provider errors, and a schema mismatch is not one.
- **The prompt does the asking, the schema does the checking.** `injectIntoSystemPrompt`/`parseOutput` on the `ai` `Output` spec are deliberately pass-throughs — AgentExecutor owns both ends so behavior is identical across providers and `ai` majors.
- **Sub-agents surface it as a tool error.** `withSubagents.ts`'s `failureReason()` turns a sub-agent's `'output-invalid'` into a `task` tool failure naming the schema issues — the lead model can retry or adapt.

## Example

```ts
import { z } from 'zod';
import { createAgent } from '@lousho/build-ai-agent';

const agent = createAgent({
  model: 'openai/gpt-4o-mini',
  output: z.object({ city: z.string(), tempC: z.number() }),
});

const result = await agent.send('Weather in Paris?');
if (result.object) console.log(result.object.tempC);          // typed
else console.error(result.finishReason, result.outputError?.issues); // 'output-invalid'
```
